Quick start

  1. Open the free scanner.
  2. Select source files from the project. The current browser release accepts up to 500 files, 20 MB total and 2 MB per file.
  3. Choose Run free scan. Files are read and analyzed in the browser tab.
  4. The free result displays only total findings and counts by severity.
Source file contents are not uploaded. The scan is static and heuristic; it does not build or execute the project.

Scan coverage

The current first-pass scanner includes pattern checks for:

  • Credential-like strings, common tokens and private-key markers.
  • Bearer authorization values.
  • Dynamic execution patterns such as eval and new Function.
  • Potential unsafe HTML assignment through innerHTML.
  • Potential shell command execution calls.
  • TLS certificate verification disabled by configuration.
  • Potential SQL string concatenation.
  • Debug logging calls.

Supported file extensions include common JavaScript, TypeScript, Python, PHP, Ruby, Go, Java, C-family, Rust, Swift, Vue, Svelte, HTML, CSS, JSON, YAML, shell and SQL files.

Free result

The free tier intentionally reveals only four numbers: total findings, high severity, medium severity and low severity. It does not display file paths, line numbers, rule IDs, evidence snippets or explanations. This is the acquisition funnel, not a security guarantee.

Paid diagnosis — $29

The AgentProof Professional Diagnosis product is published on Gumroad for $29. Buyers can enter the Gumroad license key from their receipt after running a free scan. Gumroad verifies the key server-side; the browser then reveals the findings already held locally, including file and line location, evidence and rule-specific remediation guidance. Source files and findings are not uploaded to the API. Refunded, partially refunded, chargebacked, inactive or wrong-product licenses are rejected. The license-verification endpoint has passed a live test using a valid Gumroad-issued test key.

The license verification API is a minimal Node.js service. It uses the Gumroad license verification endpoint with usage-count increment disabled, strict product matching, bounded requests, rate limiting and a single allowed browser origin. It does not store license keys.

Owner-approved local remediation

After a paid diagnosis is unlocked, the browser can prepare a repair plan. The only automatic transformation currently enabled is removal of standalone console.log and console.debug statements. Inline, conditional and multiline calls, and every other finding type, are left for manual engineering review. The owner must review the exact proposed lines and explicitly approve the change.

Before applying an approved change, AgentProof downloads a JSON backup containing the original selected source files, then downloads changed file copies separately. AgentProof does not overwrite the project directory, execute the project, upload source files, or send findings to the API. The changed copies are rescanned locally. A 100% result means zero findings remain within the current eight-rule heuristic scan scope only; it is not a security certification. Keep the backup secure because it contains the original source, and inspect every downloaded change before replacing project files.

The separate $100 Owner-Approved Remediation service remains a Gumroad draft and is not accepting payment. It will not be published until broader repair coverage and the full service delivery controls are implemented and tested.

Privacy, limitations and safe use

File reading and pattern matching occur locally in the browser. No source file upload, source code, scan findings, API key, telemetry or external AI call is sent to the license API. The license key is sent to the AgentProof API and forwarded to Gumroad for verification; it is not persisted. Browser memory is temporary; close the tab to release the in-memory file contents.

This is a limited heuristic scanner, not a full SAST, dependency auditor, runtime test suite, penetration test, compliance certification or guarantee. It can miss vulnerabilities and produce false positives. A zero-finding result means only that these configured patterns did not match the selected files.

Review every finding with a qualified engineer and use project-specific tests and security controls before deployment.
